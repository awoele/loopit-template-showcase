漏斗埋点链路与口径说明

说明事件、关联键、时间约束及当前口径的适用边界

➕唤起创作页点击漏斗

a_create_tab_clk → a_template_list_exp（list_status=ready）→ a_template_item_clk（click_target=card）→ a_template_detail_exp → a_template_use_clk（button_name=create）→ template_create_btn_clk → template_create_success

同一用户、同一天，按事件先后严格关联。全链路要求同一 pcsid；列表到 Use 要求同一 tl_sid，卡片到 Use 要求同一 template_id，Use、Create 和创建成功要求同一 template_use_id，且限定 source=template。链路次数按会话去重，每级最多计一次。

列表曝光表示列表成功加载一次，不是每张卡片各计一次。

Feed Template 点击漏斗

a_project_btn_clk（button_name=template）→ template_create_btn_clk（source=feed）→ template_create_success（source=feed）

同一用户、同一天、同一 template_use_id，按入口 → Create → 创建成功关联；Create 和创建成功限定 source=feed。人次按日去重用户求和；链路次数统计配对成功的事件，各级不会超过前一级。素材填写和辅助 Use 事件不计入。

同一 template_use_id 如有多次事件，按时间序号一一配对，避免重复串联。

作品结果漏斗

新建 PID（a_create_chat_page_exp，task_status=creating，tr_src=template）→ Task 完成（任务表 status=2）→ a_content_preview_page_exp → 项目表 D0 首次公开发布

按新建 PID 去重。Task 完成取任务表 status=2，内容预览取该 PID 的预览事件；两者未强制校验时间先后。发布成功取项目表中的 D0 公开结果，不使用仅表示按钮点击的 p_post。template_create_success 没有可稳定归因的新作品 PID；Feed 场景携带的是原作品 PID。

路径表示业务阶段，不代表严格事件时序；新建 PID 缺少稳定的 template_use_id，暂不与点击漏斗拼接。

结论边界与分析建议

结论边界

当前只能描述相关性

文档评论
使用模板的用户可能本来就是站内高活用户，因此不能直接得出“模板提升留存”的因果结论。
  • 按历史活跃天数、历史发布数和创作等级分层
  • 匹配模板组与非模板组的前置活跃度
  • 同时展示样本量、置信区间与模板组占比
  • 模板组创作者人日目前约占整体 7.3%

建议补充

用于进一步提升因果解释力

  • 每日样本量与置信区间
  • 历史活跃度分层后的留存差异
  • 模板创作者占全部创作者的比例
  • 新老创作者分别对比
